# cdn-repositories: repositories whose downloads a CDN serves

Two local generic repositories whose downloads artifactweave answers with a redirect instead
of the bytes, managed with the `jfrog/artifactory` provider: one with `cdnRedirect`, one with
`downloadRedirect` (decision
[0029](../../../../docs/research/decisions/0029-cdn-delivery-and-download-redirect.md)). Pair
it with a store that has a CDN in front of it, such as the
[`aws/cdn`](../../../platform/terraform/aws/cdn/README.md) reference deployment renders. See
[Managing artifactweave with Terraform](../../README.md) for the providers and how to
authenticate them.

## What it configures

- `artifactory_local_generic_repository.cdn`: the repository `cdn_repository_key`, with
  `cdn_redirect` (`cdnRedirect`). A download of 1 MiB or more goes to the CDN; on a store
  without one, it streams.
- `artifactory_local_generic_repository.direct`: the repository `direct_repository_key`, with
  `download_direct` (`downloadRedirect`). A download of 1 MiB or more goes to the CDN where the
  store has one, as on self-hosted Artifactory, and otherwise to a signed URL on the store
  itself; `X-JFrog-Download-Redirect-To: S3` asks for the store's URL even with a CDN.

The provider describes both flags as Enterprise+ only; artifactweave honours them on every
instance.

## Prerequisites

- A running artifactweave (or Artifactory) and its base URL, without `/artifactory`, whose
  store can sign URLs: a CDN in its `blob` configuration for `cdnRedirect`, a cloud store for
  `downloadRedirect`. On a filesystem store both repositories stream.
- An admin access token: the providers authenticate only with a Bearer token.
- Terraform 1.6 or later, which installs `jfrog/artifactory` 12.11.14 as pinned in
  `versions.tf` and `.terraform.lock.hcl`.

## Inputs to set

```hcl
url                   = "https://artifacts.example.com"
cdn_repository_key    = "generic-cdn"
direct_repository_key = "generic-direct"
```

Pass the token through the environment rather than a file: `export TF_VAR_access_token=…`.

## Applying it

```sh
terraform init
terraform apply
```

A second `terraform plan` shows no changes: the provider reads back exactly what it wrote.

## Security

The access token is a sensitive variable, so Terraform keeps it out of plans and logs. It is
still stored in the state, so keep the state private. A redirect never widens access:
artifactweave checks the caller's read permission before it signs a URL, and the signed URL
names one blob and expires (`download.redirect.ttl`, 5 minutes by default). Who can read or
deploy to the repositories is decided by the permissions you manage elsewhere, for example
with the [identity](../identity/README.md) reference.

## Teardown

`terraform destroy` removes both repositories, with every file in them. Signed URLs handed out
before then keep working until they expire.

## How this scenario is tested

The gated `terraform` job runs `test/terraform/run.sh` against a fresh `-cover` artifactweave
(see [docs/testing/ci.md](../../../../docs/testing/ci.md#terraform-scenarios)). It passes
`cdn_repository_key = tf-generic-cdn` and `direct_repository_key = tf-generic-direct`, applies,
requires an empty plan and destroys everything. The redirects themselves are proven on a real
CDN by the [`aws/cdn`](../../../platform/terraform/aws/cdn/README.md) scenario's platform
tests, which create the same two kinds of repository.
