# federated-repositories: three-member repository configuration

Manage all 35 implemented federated repository resource types with the pinned
`jfrog/artifactory` 12.11.14 provider. The resource inventory and provider mappings are
recorded in [research 40](../../../../docs/research/40-federated-repositories-7x.md#9-terraform-exit-set).
See [Managing artifactweave with Terraform](../../README.md) for authentication.

## What it configures

One three-member repository for each implemented `artifactory_federated_*_repository`
resource: 35 provider resources over 34 package types. `docker` and `docker_v2` both use
Docker V2. Terraform module and provider repositories remain distinct resources.
Docker V1 is superseded; releasebundles has no local implementation before P15;
terraformbackend has no federated provider resource and is excluded by Artifactory 7.161.26.

## Prerequisites

- Three running instances, mutually paired for `federated-repo/*`, with their base URLs
  reachable from one another. Configure the allowed private origins when using private addresses.
- An administrator access token for the first instance and, for remote deletion, each member.
- Terraform 1.17 or later; the provider and checksums are pinned in `versions.tf` and
  `.terraform.lock.hcl`.

## Inputs to set

```hcl
url = "https://artifacts-a.example.com"
member_urls = [
  "https://artifacts-a.example.com",
  "https://artifacts-b.example.com",
  "https://artifacts-c.example.com",
]
name_prefix = "fed"
```

Set `TF_VAR_access_token` and `TF_VAR_member_access_tokens` privately. The latter is a JSON
map from each base URL to its token. The provider uses member tokens only for
`cleanup_on_delete`; repository JSON carries member `url` and `enabled` fields.

## Applying it

```sh
terraform init
terraform apply
terraform plan
```

Change `description` to update all members. A refreshed plan after the update has no changes.

## Security

Token variables are sensitive, but tokens remain in Terraform state. Keep state and variable
files private. Pairing grants service trust; it does not copy administrator tokens into
configuration synchronization or repository JSON.

## Teardown

`terraform destroy` removes all repositories from all three members using
`cleanup_on_delete = true`, including their contents.

## How this scenario is tested

The required `terraform` lane starts three owned instances behind connection ownership
forwarders and pairs every combination. It applies two revisions, refreshes and requires
empty plans, reads every resource on all three members, and requires every provider
`configSync` request to return 200. The unpaired control must plan, fail apply with the native
400 naming the URL and `federated-repo/*`, and leave neither state nor repository nor a
`configSync` call. Destroy must leave all three members empty of the fixture resources.

`cover/terraform/p13-provider-evidence.json` contains sanitized provenance, all 35 resource
outcomes and the three exclusions. Private state, member credentials and runtime logs stay
in the fixture workspace. This qualifies configuration management; native content delivery
has its own acceptance scenarios.
