# OIDC scenario

OIDC token exchange for CI workload identity, managed with the `jfrog/platform` provider:
a GitHub Actions provider and a generic one, each with an identity mapping. One mapping
issues tokens for a named user; the other leaves the username out, so its tokens have a
synthetic subject that acts through the `readers` group alone (decision 0005, research 21).
The `terraform` CI job applies it against a running artifactweave, requires an empty plan
and destroys it. Nothing contacts the providers: their signing keys are fetched only when a
CI job exchanges a token. See [Managing artifactweave with Terraform](../../README.md) for
the providers and authentication.
