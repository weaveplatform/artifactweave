# package-cleanup: package policy and retained reports

This reference manages a Maven repository and one package cleanup policy with
`jfrog/artifactory` 12.11.14. Use Terraform 1.17 or later and provide `url` plus
`TF_VAR_access_token` for an administrator of the chosen instance.

Revision 1 creates the policy disabled. Revision 2 changes its description,
duration and schedule and enables it through the separate enablement operation.
The schedule is deliberately in 2099 so this example runs only when triggered
manually during qualification. `keep_last_n_versions=1` protects the latest
version in the selected repository. Choose a separate `repository_prefix` when
these keys already exist.

```sh
terraform init
terraform apply
terraform plan -detailed-exitcode
terraform apply -var revision=2
terraform plan -var revision=2 -detailed-exitcode
```

Each follow-up plan must exit zero. Terraform creates the configuration; the
required provider test additionally uploads real POM/JAR files for two Maven
versions, executes a dry run and an actual run, parses their CSV reports and
checks native downloads and rebuilt Maven metadata. It verifies that dry runs
preserve bytes, actual cleanup removes only the old version and downloaded
reports retain their original facts after deletion.

`terraform destroy -var revision=2` removes the policy and repository. Report
history remains available to authorized callers. The provider requires the
policy delete operation to return HTTP 200. Cleanup uses ordinary recoverable
trash; deduplicated report sizes describe content accounting, while physical
garbage collection runs separately.
