# package-cleanup: package policy and retained reports

This reference manages a Maven repository and one package cleanup policy with
`jfrog/artifactory` 12.11.14. It demonstrates configuration updates, separate
enablement and retained reports after cleanup and policy deletion.

## What it configures

- A local Maven repository using the `maven-2-default` layout.
- A package cleanup policy scoped to that repository in the default project.

Revision 1 creates the policy disabled. Revision 2 changes its description,
duration and schedule and enables it through the separate enablement operation.
The schedule is deliberately in 2099 so this example runs only when triggered
manually during qualification. `keep_last_n_versions=1` protects the latest
version in the selected repository. Choose a separate `repository_prefix` when
these keys already exist.

## Prerequisites

A running ArtifactWeave, an administrator access token, Terraform 1.17 or later
and the pinned Artifactory provider. This reference configures the application
and creates no cloud resources.

## Inputs to set

```hcl
url               = "https://artifacts.example.com"
repository_prefix = "managed-cleanup"
revision          = 1
```

Pass `TF_VAR_access_token` through the environment. The prefix reserves the
repository and policy keys; use an isolated namespace for cleanup exercises.

## Applying it

```sh
terraform init
terraform apply
terraform plan -detailed-exitcode
terraform apply -var revision=2
terraform plan -var revision=2 -detailed-exitcode
```

Each follow-up plan must exit zero. Terraform creates the configuration; it
does not trigger cleanup. After revision 2, an explicit run can select older
Maven versions while protecting the latest version.

## Security

The access token is a sensitive input; supply it through the environment and
protect Terraform state and saved plans. This fixture uses administrator
authority. The policy selects only its named repository in the default project,
and `skip_trashcan=false` keeps actual deletion recoverable through ordinary
trash. Use a dry run to inspect selected packages before an actual run.

## Teardown

`terraform destroy -var revision=2` removes the policy and repository. Report
history remains available to authorized callers. The provider requires the
policy delete operation to return HTTP 200. Cleanup uses ordinary recoverable
trash; deduplicated report sizes describe content accounting, while physical
garbage collection runs separately.

## How this scenario is tested

The required provider lane uses `repository_prefix=tf-p11-cleanup`, applies
revision 1 and uploads real POM/JAR files for two Maven versions. It executes a
dry run, parses its CSV report and requires an empty plan. It then applies
revision 2, checks enablement and the updated configuration, executes an actual
run and verifies retained summary and CSV facts, native downloads and rebuilt
Maven metadata. Dry runs must preserve bytes and actual cleanup must remove
only the old version. The lane requires another empty plan, destroys the
resources and checks that the policy is gone while reports retain their
original facts.
