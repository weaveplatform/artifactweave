# projects: project resources and their effective repository access

This reference creates owner, consumer and outsider projects, users, a group,
roles, an environment and repositories. Its two revisions prove that project
configuration changes actual content access, sharing and quota admission.

## What it configures

- `project.owner` exercises the planned legacy resource; `project_project.client`
  exercises its replacement alias. Provider 1.9.9 deliberately warns about the
  legacy alias; both remain in this qualification.
- `project_user`, `project_group` and `project_role` grant native access. The
  owner's user has a direct reader role and gets its initial write access through
  its project group. A separate quota writer keeps its role in both revisions.
- `project_environment.owner` creates `lab` and renames it to `lab-next`.
- `project_repository.attached` assigns an existing repository. Other repositories
  use their owning project at creation and the required project key prefix.
- `project_share_repository.consumer` shares a repository read-only, then revokes
  that share. `project_share_repository_with_all.all` changes from read-only to
  writable; current consumer roles still limit the permitted operations.
- The owner has a 1 GiB quota, hard in revision 1 and soft in revision 2. Email
  notifications are disabled in this fixture.

## Prerequisites

- Terraform **1.17 or later**; the native CI runner pins **1.17.1**.
- A running ArtifactWeave and a platform administrator access token.
- The locked providers: `jfrog/artifactory` **12.11.14**, `jfrog/platform`
  **2.2.11** and `jfrog/project` **1.9.9**.

## Inputs to set

```hcl
url             = "http://127.0.0.1:18081"
resource_prefix = "tfp11"
revision        = 1
```

Supply `access_token` and `user_password` as sensitive environment variables
`TF_VAR_access_token` and `TF_VAR_user_password`. Choose a unique resource prefix.

## Applying it

```sh
terraform init -lockfile=readonly
terraform apply
terraform plan -detailed-exitcode
terraform apply -var=revision=2
terraform plan -detailed-exitcode -var=revision=2
```

Each plan must exit 0. The native runner also reads repository ownership directly
and performs allowed and denied content operations as the created users.

## Security

The providers use the administrator token for fixture administration. Content
checks authenticate as the created project users. Removing a group role or
standard share must affect the same existing user on its next request.

Terraform retains sensitive user inputs in state. The runner keeps state in a
private work directory and retains it on failure. Its CI evidence contains only
resource names, versions, assertion results, sizes and digests.

## Teardown

```sh
terraform destroy -var=revision=2
```

The runner verifies absence of every created project, membership, role,
environment, repository, share, user and group, then stops its own application.
A failed apply or destroy preserves the private work directory for diagnosis;
`TERRAFORM_WORK` also retains a caller-selected directory on success.

## How this scenario is tested

`make terraform TERRAFORM_MODE=apply` includes this scenario in the required native
provider lane. The inventory and CI selection guard refuse an omitted resource,
runner step or lock. All four supported provider archives have pinned checksums;
the existing signed-release refresher moves the versions and locks together.

Both revisions apply and produce empty plans. Direct checks verify immediate
attachment, environment rename, group roles, cross-project denial, standard sharing
and revocation. The quota proof uploads one file of 1 GiB minus 1 MiB with bounded
memory, then requests a checksum deployment of the same content. Hard quota denies
the second logical reference; soft quota permits it without another physical upload.
Destroy is followed by public absence checks.

SQLite and PostgreSQL project/store tests independently qualify transactional
authority, ownership and quota behavior. Native evidence records the application
commit, Terraform version and provider versions.
