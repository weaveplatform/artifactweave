# trashcan: trash can policy

Set whether deletions go to the trash can, and for how long trashed items are kept, with the
pinned JFrog provider. This is the descriptor's `trashcanConfig` section, a singleton every
instance has. Use it to turn the trash can off, or to change its retention period.

## What it configures

- `artifactory_trashcan_config.this`: whether the trash can is on and its retention
  period in days. With the trash can off, a delete is final. With it on, a garbage
  collection pass purges an item once it has been trashed longer than the period; `0`
  purges it at the next pass.

## Prerequisites

- A running artifactweave or Artifactory with YAML descriptor PATCH and XML descriptor GET
  available, and its base URL without `/artifactory`.
- An admin access token.
- Terraform 1.17 or later and `jfrog/artifactory` 12.11.14, as pinned in `versions.tf` and
  `.terraform.lock.hcl`.

## Inputs to set

```hcl
url                   = "https://artifacts.example.com"
enabled               = true
retention_period_days = 30
```

Pass the token through a sensitive environment variable such as `TF_VAR_access_token`.

## Applying it

```sh
terraform init
terraform apply
terraform plan
```

The follow-up plan is empty: the provider reads both values back from the XML descriptor.
The resource is a singleton, so `terraform import artifactory_trashcan_config.this trashcan`
adopts the current policy whatever the import ID.

## Security

The access token is a sensitive input and stays out of ordinary plans and logs. Turning the
trash can off removes the means to restore a mistaken delete, and a short period shortens
the time to notice one.

## Teardown

`terraform destroy` resets the policy to its default, on with 14 days, as the provider
does: the section cannot be removed. Items already trashed stay until a collection pass
purges them under that period.

## How this scenario is tested

The required Terraform conformance lane runs this reference against its own temporary
server through `test/terraform/run.sh`. It applies revision 1 (off, 3 days) and revision 2
(on, 0 days). After each it checks, with `test/terraform/check-trashcan.py`, that the XML
descriptor reports the values and that a delete follows them: final when off, and when on
kept in the trash can until a collection pass purges it at 0 days. Each revision must
refresh to an empty plan. The driver then removes the resource from state, imports it and
requires another empty plan, destroys it and checks the reset to on with 14 days.
