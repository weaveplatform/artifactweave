# modules/aws/replication

S3 replication from one bucket to another, and the IAM role S3 assumes to do it.
[`aws/geo-replicated`](../../../aws/geo-replicated/README.md) calls it with two
[`modules/aws/storage`](../storage/README.md) buckets in different regions, passing each
module whole as `source_bucket` and `destination_bucket`. The module holds no provider block:
the replication rule names the source bucket's `region`, the per-resource region of the AWS
provider 6, and IAM is global, so one provider configuration serves both buckets without
aliases (decision
[0030](../../../../../../docs/research/decisions/0030-reference-deployments.md)). S3
replication needs versioning on both buckets, which `modules/aws/storage` turns on with
`versioning = true`.

## What it creates

- `aws_iam_role.replication`: the role S3 assumes, named `name`, under `iam_role_path` and
  carrying `permissions_boundary_arn` when they are given, and tagged with `tags`.
- `aws_iam_role_policy.replication`: what the role may do, read the source and write copies
  into the destination.
- `aws_s3_bucket_replication_configuration.replication`: one rule on the source bucket,
  copying the objects under `prefix` into the destination bucket.

## Invariants

- Only S3 may assume the role (`tests/security.tftest.hcl`, run
  `only_s3_may_assume_the_role`), and only for the source bucket in this account
  (run `trust_names_the_source_bucket_and_its_account`).
- The role reaches the source bucket, its objects and the destination's objects, and nothing
  else (`tests/security.tftest.hcl`, run
  `role_reads_the_source_and_writes_the_destination_only`), with the replication actions
  only and no delete while deletes do not replicate (run `role_gets_replication_actions_only`).
- The permissions boundary and path given reach the role (`tests/security.tftest.hcl`, run
  `boundary_and_path_reach_the_role`), and so do the tags (run `tags_reach_the_role`).
- The rule is configured on the source bucket, in its region, and copies into the
  destination (`tests/replication.tftest.hcl`, run `rule_is_on_the_source_bucket_in_its_region`)
  as the module's role (`tests/inputs.tftest.hcl`, run `the_rule_assumes_the_role`).
- Only objects under `prefix` replicate, the whole bucket when it is empty
  (`tests/replication.tftest.hcl`, runs `the_whole_bucket_replicates_by_default` and
  `only_the_prefix_given_replicates`).
- Deletes do not replicate unless `replicate_deletes` is true (`tests/replication.tftest.hcl`,
  runs `deletes_do_not_replicate_by_default` and `deletes_replicate_when_asked`).
- Replication Time Control, billed per GB replicated, is off unless asked, and then uses its
  15-minute threshold with metrics (`tests/replication.tftest.hcl`, runs
  `replication_time_control_is_opt_in` and `replication_time_control_turns_on_with_its_metrics`).
- Copies are S3 Standard unless `storage_class` names another (`tests/replication.tftest.hcl`,
  runs `copies_are_standard_by_default` and `storage_class_reaches_the_copies`).
- Both buckets must be versioned, and must differ, or the plan fails
  (`tests/inputs.tftest.hcl`, runs `an_unversioned_source_is_refused`,
  `an_unversioned_destination_is_refused` and `a_bucket_cannot_replicate_into_itself`).

## Accepted findings

None: this module carries no `#trivy:ignore`, and trivy reports nothing on it.

## Usage

Scenarios in this repository use the relative source, `../../modules/aws/replication`; anyone
else can use the git source, which names the current release.

```hcl
module "replication" {
  source = "git::https://github.com/weaveplatform/artifactweave.git//deploy/platform/terraform/modules/aws/replication?ref=v0.0.0" # x-release-please-version

  name               = "artifactweave-example-repl"
  source_bucket      = module.primary
  destination_bucket = module.replica
}
```

`module.primary` and `module.replica` are `modules/aws/storage` calls with
`versioning = true`. Passing the modules whole also orders the rule after both buckets'
versioning, which S3 requires before it accepts the rule.
