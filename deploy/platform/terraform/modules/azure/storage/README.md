# modules/azure/storage

One storage account and private container, without Shared Key, with Storage Blob Data
Contributor for the principals in `principals`. [`azure/single-bucket`](../../../azure/single-bucket/README.md)
calls it once, [`azure/multi-region`](../../../azure/multi-region/README.md) once per location,
[`azure/geo-replicated`](../../../azure/geo-replicated/README.md) once with a
`replication_type` that keeps Azure's own copies in the paired region, and
[`multicloud/mirror`](../../../multicloud/mirror/README.md) once, for its Azure mirror member.
The module holds no provider block, so the caller's `azurerm` provider and subscription apply
(decision [0030](../../../../../../docs/research/decisions/0030-reference-deployments.md)).

## What it creates

- `azurerm_storage_account.blobs`: a StorageV2 account, tagged with `tags`, replicated as
  `replication_type` says.
- `azurerm_storage_container.blobs`: the private container artifactweave writes to.
- `azurerm_storage_management_policy.cleanup`: the expiry backstops below.
- `azurerm_role_assignment.app`: Storage Blob Data Contributor on the account for each of
  `principals`.

## Invariants

- No public access: the container is private and the account refuses public containers
  (`tests/security.tftest.hcl`, run `no_blob_can_be_public`).
- TLS only: HTTPS and TLS 1.2 or later (`tests/security.tftest.hcl`, run
  `plain_http_and_old_tls_are_refused`).
- Access is identity-based: Shared Key is disabled and Entra ID is the default
  (`tests/security.tftest.hcl`, run `access_is_entra_id_only`).
- Data is encrypted at rest by Azure's service-side encryption (`tests/security.tftest.hcl`,
  run `data_is_encrypted_at_rest`).
- The principals get blob data rights on this account only, and no account administration
  (`tests/security.tftest.hcl`, run `principals_get_blob_data_rights_on_this_account_only`).
- Tags reach the account, the one resource that takes them (`tests/security.tftest.hcl`, run
  `tags_reach_the_account`).
- `<store_prefix>_uploads/` expires after 2 days (`tests/lifecycle.tftest.hcl`, run
  `abandoned_uploads_expire_after_two_days`).
- Each `expiring_prefixes` entry expires after its days (`tests/lifecycle.tftest.hcl`, run
  `expiring_prefixes_expire_after_their_days`).
- The account keeps one region's copies unless `replication_type` says otherwise
  (`tests/inputs.tftest.hcl`, runs `the_account_keeps_one_region_by_default` and
  `replication_type_reaches_the_account`).
- `secondary_host` is the paired region's read endpoint, `<account>-secondary`, when
  `replication_type` keeps a readable copy (RAGRS, RAGZRS), and null otherwise
  (`tests/inputs.tftest.hcl`, runs `a_readable_copy_has_a_secondary_host` and
  `an_unreadable_copy_has_no_secondary_host`).
- `store_prefix` is normalised as the backend does: no leading slash, one trailing slash
  (`tests/inputs.tftest.hcl`, runs `store_prefix_gains_a_trailing_slash` and
  `store_prefix_loses_a_leading_slash`).

## Accepted findings

| ID | Resource | Why |
|---|---|---|
| AZU-0012 | `azurerm_storage_account.blobs` | The account takes connections from any network, because artifactweave and the clients its signed URLs serve have no fixed addresses; with Shared Key off, every request still needs an Entra ID token or a user delegation SAS. |
| AZU-0057 | `azurerm_storage_account.blobs` | No Storage Analytics logs: the activity log records the management calls. |
| AZU-0058 | `azurerm_storage_account.blobs` | `replication_type` defaults to LRS: a mirror member keeps one region's copy and the mirror the others; a caller that wants Azure's geo-replication asks for it. |
| AZU-0060 | `azurerm_storage_account.blobs` | Microsoft-managed keys; a customer-managed key would add a Key Vault and its access policies to manage. |
| AZU-0061 | `azurerm_storage_account.blobs` | No infrastructure (double) encryption: service-side encryption already applies, and the setting can only be chosen when the account is created. |

## Usage

Scenarios in this repository use the relative source, `../../modules/azure/storage`; anyone
else can use the git source, which names the current release.

```hcl
module "storage" {
  source = "git::https://github.com/weaveplatform/artifactweave.git//deploy/platform/terraform/modules/azure/storage?ref=v0.0.0" # x-release-please-version

  account_name        = "artifactweaveexample"
  resource_group_name = "artifactweave-example-rg"
  location            = "uksouth"
  principals          = { app = { principal_id = "00000000-0000-0000-0000-00000000000a" } }
}
```
