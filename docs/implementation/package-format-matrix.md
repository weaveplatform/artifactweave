# Package format and client matrix

Generated from [the versioned inventory](package-format-inventory.json), reviewed 2026-11-18. Target: current published Artifactory 7.x contract; live target version remains #216. Classes: L=local, R=remote, V=virtual, F=federated. The [JFrog class table](https://docs.jfrog.com/artifactory/docs/repository-support-for-package-clients) omits F; F is the registered configuration contract and needs one-node native proof in each owned ticket.

`gap` means repository configuration and generic item storage exist, while the native client protocol remains owned by the linked ticket. A registered class is not a claim of native client support. `core` links proven native paths with remaining format behavior named in metadata and owned by a follow-up; `native` links completed acceptance evidence.

[Source conflicts, target-version questions and architecture contracts](package-format-inventory-notes.md) explain the class boundaries behind this matrix.

Virtual resolution describes the implementation mechanism, independently of evidence strength. `client` links a retained native-client acceptance scenario; `server` links protocol acceptance only. Neither claims P10 sign-off or cross-peer federation. See [virtual operation rules and family limits](../operations/virtual-repositories.md).
