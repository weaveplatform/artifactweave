# Package format and client matrix

Generated from [the versioned inventory](package-format-inventory.json), reviewed 2026-10-24. Target: current published Artifactory 7.x contract; live target version remains #216. Classes: L=local, R=remote, V=virtual, F=federated. The [JFrog class table](https://docs.jfrog.com/artifactory/docs/repository-support-for-package-clients) omits F; F is the registered configuration contract and needs one-node native proof in each owned ticket.

`gap` means repository configuration and generic item storage exist, while the native client protocol remains owned by the linked ticket. A registered class is not a claim of native client support. The `core` and `native` rows link existing acceptance evidence; broader class-specific completion stays with their phase owners.

[Source conflicts, target-version questions and architecture contracts](package-format-inventory-notes.md) explain the class boundaries behind this matrix.
