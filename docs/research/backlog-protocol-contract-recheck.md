## #1416: NuGet search rate limiting

**Reconfirmed:** the self-managed 7.125.4 notes (30 October 2025) announce a search rate-limiting mechanism under “Nuget Packages - Rate Limit.” They give no endpoint list, property, default, quota, scope or refusal contract. The SaaS notes repeat that announcement; the current NuGet guide has no occurrence of “rate.” These are observations about the reviewed pages, not proof that no other vendor evidence exists. [Self-managed notes](https://docs.jfrog.com/releases/docs/artifactory-self-managed-releases#artifactory-71254-self-managed), [SaaS notes](https://docs.jfrog.com/releases/docs/artifactory-saas-releases), [NuGet guide](https://docs.jfrog.com/artifactory/docs/nuget-repositories).

**Still missing:** all behavior needed to choose a limiter: v3 search versus autocomplete and v2 `Search()`/`FindPackagesById()` coverage; default enablement; time-based versus concurrent admission; user/repository/global scope; configured values; rejection status, body and headers. The issue already lists these questions; this recheck found no primary-source answer to them. [#1416](https://github.com/weaveplatform/artifactweave/issues/1416), [NuGet guide](https://docs.jfrog.com/artifactory/docs/nuget-repositories), [release announcement](https://docs.jfrog.com/releases/docs/artifactory-self-managed-releases#artifactory-71254-self-managed).

**Related evidence must remain separate:** JFrog documents AQL/search concurrency throttling, including its own enable flag, default-off behavior from 7.84.16 and 429 response. That page does not attribute those settings to the new NuGet mechanism. Inferring NuGet's policy from AQL would leave the issue's core questions unanswered. [AQL performance controls](https://docs.jfrog.com/artifactory/docs/aql-performance).

**Bounded next work:** prepare one capture matrix over local, remote and virtual repositories, the four endpoint families above, anonymous/two distinct users, sequential bursts/concurrent requests and a non-search control. Record effective configuration, request timing and complete raw responses; do not choose a guessed quota or require a guessed 429. Use the observed contract to implement only this limiter and update decision 0038. [Issue acceptance scope](https://github.com/weaveplatform/artifactweave/issues/1416).

## #1373: Debian debug packages with indexing disabled

**Additional corroboration, not a deploy answer:** the current Debian and local-repository guides describe the option as enabling debug-symbol **indexing**. The published XSD explicitly declares optional `ddebSupported` with `default="false"`; its brief description says `.ddeb` package support. Neither source specifies whether a deploy with the flag false stores the file or rejects it, nor its status/body/properties. [Debian guide](https://docs.jfrog.com/artifactory/docs/debian-repositories#local-debian-repositories), [local settings](https://docs.jfrog.com/artifactory/docs/local-repositories#additional-settings-for-debian-local-repositories), [configuration XSD](https://docs.jfrog.com/installation/docs/artifactory-configuration-xsd).

**Still missing:** current 7.x's unset/false deploy result and index/property side effects for local and federated repositories. The issue cites RTFACT-18780 for historical behavior; the Jira page could not be independently retrieved in this pass, so that historical claim is retained as issue context rather than presented as newly verified evidence. An indexing label alone does not establish admission behavior. [#1373](https://github.com/weaveplatform/artifactweave/issues/1373), [RTFACT-18780](https://jfrog.atlassian.net/browse/RTFACT-18780), [Debian guide](https://docs.jfrog.com/artifactory/docs/debian-repositories#local-debian-repositories).

**Bounded next work:** use the same valid `.ddeb` and Debian coordinates for six independent repositories/cases: local and single-node federated × omitted/false/true. Preserve upload responses, repository configuration, direct download bytes/hash, item properties and generated `Packages`; let metadata settle or explicitly trigger documented calculation. Then retain refusal or implement storage-without-indexing according to evidence. Keep remote cache behavior from #1352 outside this correction. [#1373](https://github.com/weaveplatform/artifactweave/issues/1373).

## #1271: Legacy Vagrant token endpoint

**Additional independently accessible primary evidence:** JFrog's currently published Known Issues page includes RTDEV-26518 under **7.25.7**, describing Vagrant's restricted-repository 401 and recommending a UI-created access token instead of obtaining one from `/api/vagrant/auth`. This corroborates historical endpoint usage, not continued service on the current target release. [Known Issues: 7.25.7](https://docs.jfrog.com/releases/docs/artifactory-known-issues#artifactory-7257-known-issues).

**Current documented workflow:** JFrog's Vagrant guide sets `ATLAS_TOKEN` to an existing Artifactory identity token and points `VAGRANT_SERVER_URL` at the repository API URL. The guide does not mention `/api/vagrant/auth`. That omission is insufficient evidence of endpoint removal or a migration contract. [Vagrant guide](https://docs.jfrog.com/artifactory/docs/vagrant-repositories#connect-vagrant-to-artifactory).

**Still missing:** current route existence; credentials accepted; anonymous/bad-credential answers; success media type, body, headers, token type/lifetime; successful use of any returned token; and precedence over a repository named `auth`. The issue's three legacy Jira links could not be independently retrieved in this pass, so their quoted historical details were not promoted to current findings. [#1271](https://github.com/weaveplatform/artifactweave/issues/1271), [RTFACT-9843](https://jfrog.atlassian.net/browse/RTFACT-9843), [RTFACT-17005](https://jfrog.atlassian.net/browse/RTFACT-17005), [RTFACT-26348](https://jfrog.atlassian.net/browse/RTFACT-26348).

**Bounded next work:** capture the route with valid Basic credentials, invalid Basic credentials and anonymous access, first without and then with a Vagrant repository named `auth`. Preserve the full response and test any returned credential against the catalog and a box download. If current 7.x serves it, implement the observed behavior and record any necessary token deviation; otherwise document the evidence and close the compatibility question. Do not manufacture a token endpoint from historical examples. [#1271 acceptance and decision branches](https://github.com/weaveplatform/artifactweave/issues/1271).
