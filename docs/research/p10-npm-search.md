# P10 npm virtual search

Research date: **2026-11-18**. Scope: [NPM-03 / #1567](https://github.com/weaveplatform/artifactweave/issues/1567), using its `cover/npm-03/issue-1567.md` snapshot and Artifactory **7.161.26** source. No trial or live Artifactory capture was used.

**[D]** means official documentation, **[KB]** JFrog knowledge base, **[J]** public JFrog Jira, **[S]** inspected first-party source, and **[I]** a choice public evidence does not settle. Generic artifact resolution and UI/AQL search do not establish the native `/-/v1/search` merge algorithm.

## [I] decisions recorded on [#216](https://github.com/weaveplatform/artifactweave/issues/216#issuecomment-6972717811)

The NPM-03 rules below are implementable choices consistent with the evidence, but remain unverified Artifactory native-search details:

1. Concatenate member results in ENG-08 effective order; de-duplicate by exact package name with the first eligible member winning. No source settles cross-member version selection, relevance ordering, or name de-duplication.
2. Apply member read/source rules and virtual/nested/member path patterns to `.npm/<name>/package.json` **before** merged paging. Access restrictions are documented; that exact search-hit path and sequence are not. Follow product R5 regardless.
3. Retain at most `min(from+size,500)` eligible unique names per member, after policy/Read filtering and earlier-member duplicate removal, then page the merged names once. Local candidate windows are at most 500 with no total scan cutoff. Remote windows grow to 500; at most 32 upstream pages per member/request and 64 MiB of retained objects bound malformed/non-progressing sources. Exhausting that ceiling passes over the whole remote contribution rather than silently returning a partial sample. These defensive limits and the eligible-hit budget are ours.
4. Cache **remote member search answers** by virtual, member, normalized query and visibility for the virtual period; read local members live. Documentation supports retrieval-period freshness but does not settle this placement, key, visibility strategy, or whether a virtual cache expiry bypasses a still-fresh remote cache.
5. Skip unreadable, blacked-out, offline, or failing members and return 200 with remaining hits, including an empty `objects` array when none survive. A native-search guarantee for 4xx/5xx, malformed JSON, timeout and stale cached-search fallback was not found.
6. Use `{"objects":[{"package":{...}}]}` without `total`/`time` for virtual search, preserving eligible remote objects' additional fields. The local envelope is captured; this virtual envelope and remote-field preservation are inferred.
7. Keep an invalid-SemVer result unchanged. Not failing the overall search is settled intended behavior; retaining that particular hit is not.

Implementation seam: reuse the ordered member walk, member request authorization/source policy, and a visibility-keyed raw member-page cache beside ENG-07's existing filtered-part cache; keep the pure name merge and final slicing in the npm format package. Recheck visibility and current member policy on cache hits. No SemVer ordering is needed to implement the chosen first-name-wins merge.
